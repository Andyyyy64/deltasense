Additional checks cover exact IoU threshold inclusion, zero-area boxes, incompatible
classes, unknown class filters, nonfinite scores/coordinates, fractional class IDs,
missing class names, inconsistent raw array shapes and mask mappings, nonbinary
masks, source/mask snapshot protection (including write-flag and shape changes),
repeated/concurrent comparisons, grayscale,
palette transparency, CMYK JPEG, alpha-on-white, all four 16-bit PNG color families/animated PNG
rejection, image size limits, unreadable files, symlink loops, invalid setting types,
conflicting offline settings, wrong result count/type, and unsupported-device failure
without fallback.

The generated properties check count union/reversal, exact displacement from known
coordinates, mask-support conservation, IoU symmetry/bounds/degeneracy, arbitrary
matching graph partitions/permutations, and malformed-image error classification.
Mutation checks deliberately invert count/area/displacement signs, change the IoU
boundary, allow cross-class/forced matching, use the wrong ratio denominator,
replace XOR by union, advertise verified physical change, and silently binarize
invalid masks. Tests must detect each mutation independently in an isolated source
copy. Source files are never modified by that audit.

| Source | Scene and expected visible content | Rights and credit |
|---|---|---|

| `coffee.png` | Coffee cup, spoon, table | Rachel Michetti, CC0; courtesy Pikolo Espresso Bar, documented by [scikit-image](https://scikit-image.org/docs/stable/api/skimage.data.html#skimage.data.coffee) |
| `chelsea.png` | Cat | Stefan van der Walt, CC0, documented by [scikit-image](https://scikit-image.org/docs/stable/api/skimage.data.html#skimage.data.chelsea) |
| Apollo 11 DAC film | Fixed lunar-module-window camera, astronaut activity and lunar foreground | NASA [Apollo 11 Video Library](https://www.nasa.gov/wp-content/uploads/static/history/alsj/a11/video11.html) explicitly identifies clips as public domain; digitization by Gary Neff, footage courtesy John Knoll |

Static source PNGs are pinned to scikit-image tag `v0.25.2`. Asset URLs and source
SHA-256 values are in `scripts/prepare_validation.py`. Models come from the official
Ultralytics assets `v8.4.0` release. Weights and images are never bundled into the
library wheel/source distribution. Their licensing is independent of the deferred
DeltaSense project license decision.

Each static photograph has 21 variants: identical pixels, four brightness factors,
three blur strengths, three occlusion widths, three image translations, two image
scales, blank, mirror, two JPEG qualities, and EXIF-oriented JPEG. These are
controlled digital edits, not independent camera captures and not physical object
growth/movement ground truth. Image translations/scales are deliberate violations
of the aligned-input assumption; results must retain unchecked conditions.

Apollo video frames are extracted at playback timestamps 30, 120, and 121 seconds.
The 120/121-second pair contains distinct captured frames with fixed framing and
no visually apparent localized subject addition/removal. It is a recapture example,
not a claim that illumination, shadows, or every physical scene detail is invariant.
The 30/120-second pair contains a visible subject-presence difference. Capture
assumptions are manually stated; DeltaSense does not verify them.

Actual baseline predictions with the verified runtime:

| Pair/source | Detection model | Segmentation model |
|---|---|---|
| Astronaut, identical | person 1 → 1 | person 1 → 1 |
| Coffee, identical | cup 1 → 1; spoon 1 → 1; dining table 1 → 1 | cup 1 → 1; dining table 1 → 1 |
| Chelsea, identical | cat 1 → 1 | cat 1 → 1 |
| Apollo 120 → 121 s | person predictions 1 → 2 | person predictions 1 → 1 |
| Apollo 30 → 120 s | cow predictions 1 → 0; person predictions 0 → 1 | person predictions 2 → 1 |

The Apollo detections include false positives: there is no cow in the lunar scene,
and the 120/121-second person-count increase is not evidence of a new astronaut.
This failure is preserved in the evidence rather than hidden. The API correctly
reports model predictions and leaves physical change unverified. The coffee spoon
is also missed by the segmentation checkpoint at the selected threshold.

Identical astronaut pixels produced approximately -0.000027/-0.000024 pixel center
differences and a +0.01338 pixel-squared bbox area difference in batch CPU detection
inference. DeltaSense preserves these numerical prediction differences. A01's
exact-zero arithmetic is verified on identical **observations**, not inferred from
identical **inputs**. This distinction is essential for small-change applications.

## Reproduce locally

Install the CPU runtime/library/development dependencies as in the README. Explicit
network-enabled provisioning (requires `ffmpeg` on PATH):

```sh
.venv/bin/python scripts/prepare_validation.py --output artifacts
```

No model/data provisioning occurs during ordinary tests or library comparisons.
Then run deterministic and mutation checks:

```sh
.venv/bin/ruff check src tests scripts
.venv/bin/ruff format --check src tests scripts
.venv/bin/pytest --cov=deltasense --cov-branch --cov-fail-under=100
.venv/bin/python scripts/mutation_check.py --output artifacts/mutations-final
```

On Linux with unprivileged user/network namespaces enabled, run explicit real-model
checks offline. Other hosts must provide equivalent network isolation; lack of
that capability is unverified, not a passing offline check.

```sh
mkdir -p artifacts/yolo-config
YOLO_CONFIG_DIR="$PWD/artifacts/yolo-config" \
  unshare --user --map-root-user --net .venv/bin/python scripts/validate_real.py \
  --models artifacts/models --sources artifacts/sources \
  --output artifacts/real-validation --require-isolated-network
```

The script checks arithmetic/partition/JSON consistency, records actual model
outputs, saves headless plots explicitly, reverses pairs, validates confidence/class/
max-detection/image-size settings, checks corrupt-input behavior after upstream
import, and checks unsupported-device failure. It verifies source-image hashes
and records networking audit events (must be empty). Device/model identity,
software versions, settings, input hashes, and elapsed times are saved; no speed
or model-accuracy promise is inferred from them.

Build a source distribution and wheel (`uv build`, or `python -m build`), install
the wheel into a separate venv with provisioned CPU dependencies, and repeat the
tests and explicit real-model run from a directory outside the source tree. Confirm
`deltasense.__file__` points into the wheel environment's `site-packages`. The local
verification uses `.venv-wheel`: tests run from `artifacts/clean-cwd`, and the
real-model workflow and public quickstart run from `/tmp/deltasense-wheel-smoke`,
outside the repository.

## Remaining boundaries

This local candidate implements the v0.1 comparison scope. It does not implement
v0.2 registration, capture-quality scoring, physical units, exact contour analysis,
tracking over three or more timepoints, custom training, or a product CLI/web UI.
Conservative matching can leave genuinely corresponding objects unresolved. The
small real dataset does not establish performance on a user's unseen domain.

An additional, explicitly provisional annotated pilot now measures scoped
detection, signed count changes, and correspondence on 13 images / 14 pairs.
Its labels are assistant visual annotations, not independently human-reviewed
ground truth. See [the Japanese accuracy report](accuracy.md) and
[the frozen dataset/reproduction protocol](../evaluation/README.md).
The original 219-case evidence above remains the historical baseline; the
additional 20 scoring checks bring the current deterministic suite to 239 cases,
with source statement/branch coverage still 100%. New run evidence is separate
under `artifacts/accuracy-pilot/` so the earlier results remain auditable.

A further published-human-annotation evaluation uses a frozen MOT17 subset:
96 images, 72 pairs, two checkpoints and three inference configurations.
See [the Japanese MOT17 report](mot17-accuracy.md) for detection, correspondence,
visibility/time-gap breakdowns, failure attribution, and exploratory settings.
Its raw-count diagnostics are explicitly not calibrated physical-change rates.
Dataset files and copied ground truth remain in ignored local artifacts;
the source distribution includes only the sampling plan and asset fingerprints.
Scoring, conversion, bounded ZIP retrieval, and diagnostic checks bring the
current deterministic suite to 262 cases. Source coverage remains 100%.

At the time of this local snapshot, remote CI, a chosen license/publication
destination, a published artifact, and release read-back were outstanding.
Source integration and remote CI are now tracked separately in the links above.
The GitHub v0.1 milestone must remain open until
those delivery requirements are satisfied. Local implementation, local verification,
